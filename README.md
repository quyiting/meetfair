# MeetFair · 聚点

[![CI](https://github.com/quyiting/meetfair/actions/workflows/ci.yml/badge.svg)](https://github.com/quyiting/meetfair/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

一个原生微信小程序：先创建聚会并邀请，再由 2–8 位参与者各自提交位置，推荐整体通勤更公平的聚会地点与时间。

> 当前项目处于 MVP 阶段，适合学习、试用和二次开发；上线前请完成隐私合规、数据库权限和真机验收。

## 功能

- 发起人无需先填写位置即可创建云端房间，通过小程序链接或 6 位码邀请朋友；参与者各自填写位置、交通方式和预算。
- 支持当前位置、手动选点和地址近似定位。
- 按“照顾最远的人”“全员总时间最短”“大家时间最接近”三种目标生成建议。
- 可接入腾讯位置服务或高德 Web 服务获取候选地点和路线；路线服务不可用时标记估算结果。
- 创建时选择 1–3 个候选日期和 1／2／3 小时聚会时长；成员逐日期填写可用时间或明确标记“这天没空”，按完整聚会时长给出日期与时间建议。
- 创建时可选填预计人数（2–8 人，含自己，默认不确定）；房间顶部展示位置和时间填写进度、已提交成员的状态，并引导当前用户完成下一步。预计人数仅作参考，不改变两人即可开始推荐的规则。
- 成员可修改自己的位置和出行信息；创建者可确认最终地点与时间。
- 最终时间与地点齐全后，成员可答复参加／待定／不参加；实际变更方案会清空旧意向并要求重新确认，重复确定相同方案不影响答复。
- 已加入成员可从地图选点提名公共地点（最多 8 个），与自动搜索结果统一比较和投票；刷新附近不清除提名，未知价格、评分不会编造。
- 首页可筛选个人待填写、协商中、已确定和已结束房间；创建者可手动结束协商，结束后仍可查看、导航、退出或删除。支持“再约一次”安全预填活动信息，不复制成员位置和旧方案。
- 两人加入后自动尝试首次推荐；后续成员变化由发起人或已加入成员手动更新地点与路线。
- 通过 6 位房间码或小程序链接共享房间，并使用云函数同步成员、候选地点和投票。
- 未加入者只看到房间摘要；旧房间预填席位仍可通过认领码加入。支持离开房间、删除房间和过期房间清理。

## 使用流程

1. 发起人填写聚会名称、类型和时间，直接创建云端房间；此时无需提交任何人的位置。
2. 在房间页分享小程序链接，或复制 6 位聚会码。朋友打开后，各自填写姓名、出发位置、交通方式和预算；发起人也可以稍后填写。
3. 第 2 人提交位置后，客户端自动尝试一次地点推荐。若地图服务失败，成员信息仍会保留，可在房间页点击“生成推荐”重试。
4. 后续成员或时间变化会提示推荐待更新；新房间中发起人或任一已加入成员可手动更新，发起人可确认最终地点与时间。
5. 成员可提名自己熟悉的公共地点、逐天答复可用时间；创建者确定完整方案后，大家确认是否参加。实际更改日期、时间或地点后需重新确认。
6. 结束聚会后不再接受加入、编辑、提名和投票；位置仍按原保留期限删除。“再约一次”只预填活动设置并把日期重置为今天，点击创建才生成新的空成员房间。

只有 1 人提交位置时，也可从顶部进度卡先填写可用时间。未提交位置的受邀者尚未列入成员名单；预计人数达到后也不代表所有人已填写时间。旧房间未设置预计人数时，只展示实际填写进度，不显示预计总数。

预计人数通过 `roomService` 建房请求中的可选字段 `expectedMemberCount` 保存：省略或 `0` 表示不确定，其他值必须为 2–8 的整数；它不是人数上限或推荐触发条件。升级部署方式见下文，无需迁移旧房间数据。

## 地点与店铺数据来源

饭店、电影院、咖啡店和娱乐场所来自地图服务的周边 POI 搜索，不是美团、大众点评或猫眼的商家接口。

| 来源 | 当前用途 | 数据边界 |
| --- | --- | --- |
| 腾讯位置服务 | 周边地点名称、地址、坐标等 | 当前实现不提供店铺价格，缺失字段不补造 |
| 高德 Web 服务 | 周边地点及部分真实通勤路线 | 价格、评分、营业时间取决于接口返回，不保证每家都有 |
| 成员地图选点提名 | 把熟悉的公共地点加入讨论、比较和投票 | 不提供价格、评分；无真实路线时使用估算 |

云函数检测到 `AMAP_KEY` 时优先使用高德，否则使用腾讯位置服务；同时配置两个 Key 不会自动轮换或故障切换。当前真实路线查询仅实现高德，未配置高德时使用估算通勤时间。自动推荐优先为各类别首选地点、再补足至最多 6 个候选请求真实路线，不代表最终列表所有地点都有真实路线覆盖。

尚未接入团购券、实时优惠、电影排片、票价或购票。地图价格与评分不能当作实际交易报价，营业状态也仅供参考。预算缺失时不会编造人均消费；“安静、包间、停车”等偏好仅在地点资料有明确线索时辅助同等通勤候选的排序。

## 推荐逻辑

推荐会综合参与者到候选地点的路线时间，并按所选目标排序：

- **照顾最远的人**：优先降低最长单人通勤时间。
- **全员总时间最短**：降低所有成员通勤时间之和。
- **大家时间最接近**：降低成员之间的通勤时间差异。

交通方式、预算和地点偏好会参与筛选或评分。路线接口不可用时，页面会明确标记估算状态，不会把直线距离伪装为真实路线。

新建房间在第 2 人提交位置后自动尝试一次推荐；搜索失败不会撤销成员加入，已加入成员可重试。之后成员变化时，旧地点与路线会标为待更新，由任一已加入成员或发起人手动刷新；旧房间仍仅发起人可刷新。地点列表会说明首选与第二名的主要通勤差异及真实路线覆盖人数。

每位成员可为每个候选日期填写最多 5 段可用时间；相接或重叠时段按并集覆盖完整聚会时长，同一人只计一次。未填写不等于没空，进度完成须答复全部候选日期。当天会预留预计通勤时间。旧单日期房间默认 1 小时，旧答复只归属原日期。创建者确定新日期或时间后，旧路线清除并拒绝旧日期搜索回写；地点营业状态和路线需重新查询。

手动提名与自动候选独立保存，最多共展示 100 个候选且优先保留提名。同规范化名称且相距 30 米以内的重复提名会合并；不同分店不会仅因同名合并。提名者或房主可删除尚未最终选中的提名，最终地点需先更换才能删除。路线失败不撤销已保存提名，会保留估算提示；单人房间不展示多人公平指标。

## 快速开始

### 前置条件

- [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
- 已开通的微信云开发环境
- Node.js 20 或更高版本
- 腾讯位置服务或高德开放平台的 Web 服务密钥

### 本地运行

```bash
git clone https://github.com/quyiting/meetfair.git
cd meetfair
npm test
```

根目录测试仅使用 Node.js 内置模块，不需要先安装前端依赖；云函数依赖在上传时由云端安装。`npm test` 不会部署云函数或创建真实房间。

随后用微信开发者工具导入项目，并完成以下替换：

1. 将 `project.config.json` 中的 `appid` 替换为你自己的小程序 AppID。
2. 将 `miniprogram/app.js` 和 `cloudbaserc.json` 中的云环境 ID 替换为你自己的环境。
3. 在云端配置地图服务密钥，不要把密钥写入小程序端或提交到 Git。

AppID 和云环境 ID 是项目标识，不等同于服务端密钥；公开仓库仍建议使用自己的标识，避免误部署到他人的环境。

## 云开发部署

首次部署建议按以下顺序操作：

1. 在项目的 `cloudfunctions` 根目录选择自己的云环境，并核对 `miniprogram/app.js` 与 `cloudbaserc.json` 中的环境 ID。
2. 在云开发数据库创建 `rooms` 和 `roomSignals` 集合，设置下述权限规则。
3. 逐个右键云函数目录，选择“上传并部署：云端安装依赖”；地图密钥只配置在 `venueService` 的云端环境变量中。
4. 核对清理函数的定时触发器已生效，再重新编译小程序。
5. 创建保留 1 小时的独立测试房间，用两个微信身份验证加入、时间填写、推荐与确认，不要修改已有真实聚会来验收。

云函数职责：

- `roomService`：房间、成员身份、多日期日程、提名、投票、方案意向及结束操作；新增辅助文件也必须一同部署。
- `venueService`：地点搜索和路线查询，服务端持有地图密钥。
- `cleanupExpiredRooms`：清理过期房间及相关信号；目录内 `config.json` 提供每小时触发配置，须在目标环境确认触发器已部署。

更新小程序代码后，需重新部署受影响的云函数并重新编译小程序。新流程只有云端建房成功才会保存和进入可分享房间；云端不可用时留在创建页重试。旧本机房间及长码仍可打开并按原流程重试同步。

本版本修改了 `roomService` 的日程、方案意向、提名及结束逻辑，更新代码后必须将 **整个 `cloudfunctions/roomService` 目录**重新上传并部署到小程序当前选择的云环境（包括新增的四个辅助 JS 文件）。仅重新编译小程序不会更新云端函数；若仍提示“未知操作”或行为未变化，先核对环境与函数部署版本。不需要批量迁移旧房间。本轮已在用户授权的环境部署并完成部分云端验收，其他部署环境仍需自行上传，详见验证记录。

本地回归、模板编译与模拟器检查不等于真实云端双身份或真机验收；具体证据和待验收场景见 [本轮验证记录](tasks/verification-2026-10-15.md)。

为 `venueService` 配置所选地图服务的环境变量：

| 地图服务 | 必填 | 使用签名校验时 |
| --- | --- | --- |
| 高德 | `AMAP_KEY` | `AMAP_SK` |
| 腾讯位置服务 | `QQ_MAP_KEY` | `QQ_MAP_SK` |

只配置实际使用的服务。Key 须具备相应 Web 服务权限；如已开启签名校验，必须同时配置对应的 SK。仓库不提供可直接使用的地图凭证。

数据库权限建议：

- `rooms` 禁止小程序端直接读写，所有操作通过 `roomService` 完成。
- `roomSignals` 只允许已登录用户读取自己的信号记录，禁止小程序端直接写入。可使用安全规则 `{"read": "doc.openid == auth.openid", "write": false}`。

`venueService` 对相同区域、类别和聚会时间的地点搜索使用单个云函数实例内 5 分钟缓存；实例更换后缓存不会保留。云函数日志仅记录操作、服务商、耗时、结果数量和缓存命中次数，不记录坐标或地图密钥。

腾讯地点搜索按 5 QPS 配额预留余量：同一云函数实例内的请求至少间隔 250 毫秒，首次搜索多个区域和类别时会花费几秒。遇到每秒限流（状态码 `120`）会退避并最多重试两次；每日额度或签名错误不会自动重试。排队和冷却在单个实例内共享，多个云函数实例及其他应用共用同一个 Key 时，仍可能达到总配额；持续限流会提示稍后再试。需要重新部署 `venueService` 才能启用此处理。

### 常见问题

- 提示云函数不存在：确认开发者工具已选中正确的云环境，并上传部署 `roomService` 和 `venueService`。
- 提示在 `cloudfunctionRoot` 选择云环境：在文件树 `cloudfunctions` 根目录关联云环境，不是只打开云控制台；随后再上传函数。
- 提示“未知操作”或新功能未生效：核对上传的是整个新版 `roomService` 目录，以及小程序初始化环境与部署环境一致。
- 首次推荐出现 `Cannot create field 'label' in element {venueSource: null}`：确认已部署本版本的 `roomService`；旧版本会在将空地点来源更新为对象时失败。
- 提示地图 Key 未配置或签名失败：检查 `venueService` 所在云环境的地图密钥及签名密钥，修改环境变量后重新部署该函数。不要将密钥写入仓库。
- 提示每秒请求量达到上限：检查同一 Key 是否被其他应用或云函数实例共用，并查看地图服务配额；稍后重试不一定能解决持续占用。
- 提示 `Invoking task timed out after 3 seconds`：在云函数配置中检查执行超时，结合日志确认耗时来自搜索、排队还是路线请求；仅延长客户端等待时间不能解除服务端超时。
- 电脑与手机行为不同：先确认已重新生成预览且使用相同云环境。清除手机本地缓存不会更新云函数，也不会删除云端房间或重置地图 Key 配额。

## 隐私与数据

- 房间位置仅用于本次推荐；新房间的未加入受邀者只能看到名称、类型、时间与人数，不会收到成员坐标。
- 创建时可选保留 1 小时、1 天、7 天或 30 天，默认 30 天。过期后不可继续访问；物理删除依赖清理函数成功运行，不承诺到期瞬间完成。
- “结束聚会”只停止协商，不立即删除位置；房主可删除整个房间，成员可退出并删除自己的位置信息。“再约一次”不复制成员位置、投票或参加意向。
- 请勿提交真实地图密钥、OpenID、房间码、精确住址或生产数据。
- 本项目没有替代你在微信公众平台完成的隐私声明、用户授权和数据保留策略配置。

## 当前限制

- 云端通过私人信号文档触发页面拉取；订阅不可用时可下拉手动同步。
- 新房间由发起人或任一已加入成员刷新全员候选地点；旧房间仍仅创建者可刷新。
- 真实路线请求只覆盖排名靠前的候选地点，其余结果可能使用估算值。
- 地图服务配额、签名、域名白名单和网络状态会影响地点与路线结果。
- 尚未提供完整的无障碍、国际化和自动化真机测试。
- 当前优先补齐双身份与真机验收；后续再考虑更完整的地点资料和第三方商业数据，不将尚未接入的服务作为现有能力。
