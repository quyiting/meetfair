# MeetFair · 聚点

[![CI](https://github.com/quyiting/meetfair-wechat-miniapp/actions/workflows/ci.yml/badge.svg)](https://github.com/quyiting/meetfair-wechat-miniapp/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

一个原生微信小程序：先创建聚会并邀请，再由 2–8 位参与者各自提交位置，推荐整体通勤更公平的聚会地点与时间。

> 当前项目处于 MVP 阶段，适合学习、试用和二次开发；上线前请完成隐私合规、数据库权限和真机验收。

## 功能

- 发起人无需先填写位置即可创建云端房间，通过小程序链接或 6 位码邀请朋友；参与者各自填写位置、交通方式和预算。
- 支持当前位置、手动选点和地址近似定位。
- 按“照顾最远的人”“全员总时间最短”“大家时间最接近”三种目标生成建议。
- 可接入腾讯位置服务或高德 Web 服务获取候选地点和路线；路线服务不可用时标记估算结果。
- 根据成员时间段交集给出聚会时间建议。
- 成员可修改自己的位置和出行信息；创建者可确认最终地点与时间。
- 两人加入后自动尝试首次推荐；后续成员变化由发起人或已加入成员手动更新地点与路线。
- 通过 6 位房间码或小程序链接共享房间，并使用云函数同步成员、候选地点和投票。
- 未加入者只看到房间摘要；旧房间预填席位仍可通过认领码加入。支持离开房间、删除房间和过期房间清理。

## 使用流程

1. 发起人填写聚会名称、类型和时间，直接创建云端房间；此时无需提交任何人的位置。
2. 在房间页分享小程序链接，或复制 6 位聚会码。朋友打开后，各自填写姓名、出发位置、交通方式和预算；发起人也可以稍后填写。
3. 第 2 人提交位置后，客户端自动尝试一次地点推荐。若地图服务失败，成员信息仍会保留，可在房间页点击“生成推荐”重试。
4. 后续成员或时间变化会提示推荐待更新；新房间中发起人或任一已加入成员可手动更新，发起人可确认最终地点与时间。

## 推荐逻辑

推荐会综合参与者到候选地点的路线时间，并按所选目标排序：

- **照顾最远的人**：优先降低最长单人通勤时间。
- **全员总时间最短**：降低所有成员通勤时间之和。
- **大家时间最接近**：降低成员之间的通勤时间差异。

交通方式、预算和地点偏好会参与筛选或评分。路线接口不可用时，页面会明确标记估算状态，不会把直线距离伪装为真实路线。

新建房间在第 2 人提交位置后自动尝试一次推荐；搜索失败不会撤销成员加入，已加入成员可重试。之后成员变化时，旧地点与路线会标为待更新，由任一已加入成员或发起人手动刷新；旧房间仍仅发起人可刷新。地点列表会说明首选与第二名的主要通勤差异及真实路线覆盖人数。每位成员可为创建者选定的日期填写最多 5 段可用时间；建议按 1 小时聚会时长计算，当天会预留预计通勤时间。创建者确定新时间后，地点营业状态和路线需重新查询。

## 快速开始

### 前置条件

- [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
- 已开通的微信云开发环境
- Node.js 20 或更高版本
- 腾讯位置服务或高德开放平台的 Web 服务密钥

### 本地运行

```bash
git clone https://github.com/quyiting/meetfair-wechat-miniapp.git
cd meetfair-wechat-miniapp
npm test
```

随后用微信开发者工具导入项目，并完成以下替换：

1. 将 `project.config.json` 中的 `appid` 替换为你自己的小程序 AppID。
2. 将 `miniprogram/app.js` 和 `cloudbaserc.json` 中的云环境 ID 替换为你自己的环境。
3. 在云端配置地图服务密钥，不要把密钥写入小程序端或提交到 Git。

AppID 和云环境 ID 是项目标识，不等同于服务端密钥；公开仓库仍建议使用自己的标识，避免误部署到他人的环境。

## 云开发部署

在微信开发者工具中上传并部署以下云函数：

- `roomService`：房间、成员、投票和身份操作。
- `venueService`：地点搜索、逆地址解析和路线查询。
- `cleanupExpiredRooms`：清理过期房间；需在云端按需配置定时触发器。

更新小程序代码后，需重新部署受影响的云函数并重新编译小程序。新流程只有云端建房成功才会保存和进入可分享房间；云端不可用时留在创建页重试。旧本机房间及长码仍可打开并按原流程重试同步。

本版本修改了 `roomService` 的建房、加入和推荐写入逻辑，更新代码后必须将它重新上传并部署到小程序当前选择的云环境。仅重新编译小程序不会更新云端函数；若修复后仍看到旧错误，先核对实际调用的环境与函数部署版本。

为 `venueService` 配置所选地图服务的环境变量：

| 地图服务 | 必填 | 使用签名校验时 |
| --- | --- | --- |
| 高德 | `AMAP_KEY` | `AMAP_SK` |
| 腾讯位置服务 | `QQ_MAP_KEY` | `QQ_MAP_SK` |

数据库权限建议：

- `rooms` 禁止小程序端直接读写，所有操作通过 `roomService` 完成。
- `roomSignals` 只允许已登录用户读取自己的信号记录，禁止小程序端直接写入。可使用安全规则 `{"read": "doc.openid == auth.openid", "write": false}`。

`venueService` 对相同区域、类别和聚会时间的地点搜索使用单个云函数实例内 5 分钟缓存；实例更换后缓存不会保留。云函数日志仅记录操作、服务商、耗时、结果数量和缓存命中次数，不记录坐标或地图密钥。

腾讯地点搜索按 5 QPS 配额预留余量：同一云函数实例内的请求至少间隔 250 毫秒，首次搜索多个区域和类别时会花费几秒。遇到每秒限流（状态码 `120`）会退避并最多重试两次；每日额度或签名错误不会自动重试。排队和冷却在单个实例内共享，多个云函数实例及其他应用共用同一个 Key 时，仍可能达到总配额；持续限流会提示稍后再试。需要重新部署 `venueService` 才能启用此处理。

### 常见问题

- 提示云函数不存在：确认开发者工具已选中正确的云环境，并上传部署 `roomService` 和 `venueService`。
- 首次推荐出现 `Cannot create field 'label' in element {venueSource: null}`：确认已部署本版本的 `roomService`；旧版本会在将空地点来源更新为对象时失败。
- 提示地图 Key 未配置或签名失败：检查 `venueService` 所在云环境的地图密钥及签名密钥，修改环境变量后重新部署该函数。不要将密钥写入仓库。
- 提示每秒请求量达到上限：检查同一 Key 是否被其他应用或云函数实例共用，并查看地图服务配额；稍后重试不一定能解决持续占用。

## 隐私与数据

- 房间位置仅用于本次推荐；新房间的未加入受邀者只能看到名称、类型、时间与人数，不会收到成员坐标。
- 房间数据会记录创建与过期时间，可由房主删除，也可通过清理云函数删除过期数据。
- 请勿提交真实地图密钥、OpenID、房间码、精确住址或生产数据。
- 本项目没有替代你在微信公众平台完成的隐私声明、用户授权和数据保留策略配置。

## 当前限制

- 云端通过私人信号文档触发页面拉取；订阅不可用时可下拉手动同步。
- 新房间由发起人或任一已加入成员刷新全员候选地点；旧房间仍仅创建者可刷新。
- 真实路线请求只覆盖排名靠前的候选地点，其余结果可能使用估算值。
- 地图服务配额、签名、域名白名单和网络状态会影响地点与路线结果。
- 尚未提供完整的无障碍、国际化和自动化真机测试。
